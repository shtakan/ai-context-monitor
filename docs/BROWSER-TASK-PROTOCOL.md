# BROWSER-TASK-PROTOCOL.md

**Назначение:** дешёвый и предсказуемый протокол выполнения браузерных задач (перехват трафика и DOM через BrowserSkill/bsk) без «квадратичного» роста расхода токенов.

**Область:** все задачи, где работать нужно в живой вкладке Chrome через `bsk_*` / `browser_*` инструменты. Применяется поверх `Протокол Правды.txt` и `CLINE_PROMPT_RULES.md`.

**В релизный ZIP не входит** (фильтр `\.md$` в `.github/workflows/release.yml:110`).

**Версия:** 1.0 (сформирован 2026-10-23 по итогам задачи m00001 — перехват вложения TXT в чате DeepSeek; израсходовано ≈8,5 M tok, из них основная часть — на проброс окружения и на повторную отправку накопленного контекста).

---

## §1. Принцип

Дорогая браузерная задача — это не «мало вызовов», а **мало прочитанного в контекст**. Каждый ответ инструмента становится частью контекста и, начиная примерно с 40-го шага, оплачивается повторно на каждом следующем шаге. Поэтому бюджет ставится не на количество вызовов, а на **объём принятых данных**: тяжёлое уходит в файл, в контекст попадают только вывод и выдержка.

Три правила, которые дают основной эффект:

1. **Тяжёлый ответ — в файл, не в контекст.** Любой результат больше ~2–3 тыс. токенов (дамп страницы, экспорт перехвата, дерево доступности, бандл) сохраняется на диск и анализируется в shell (`grep`, `head`, `jq`, `python`); в контекст возвращается ≤20 строк.
2. **Одно решающее измерение вместо доказательства всего.** Формулируется один вопрос, ответ на который закрывает задачу; остальные гипотезы не проверяются.
3. **Чужой опыт не переоткрывается.** То, что уже описано в `docs/BSK-CHEATSHEET.md` (лимиты, тупики, порт демона), проверяется одной командой, а не исследованием.

## §2. Бюджет и стоп-условия

| Параметр | Значение |
|---|---|
| Вызовов инструментов на задачу | ≤ 40 (норма — 12–20) |
| Вызовов на одну фазу (подключение / DOM / сеть / вывод) | ≤ 6 |
| Неудачных попыток на одну гипотезу | ≤ 3, затем смена гипотезы |
| Токенов на один ответ инструмента в контексте | ≤ 2 000 (иначе — файл) |
| Выдержек чужого контента в отчёте | ≤ 20 строк |

**Стоп-условия (немедленно к выводу с блокером, а не к новому исследованию):**

- `bsk status` показывает `browsers connected 0` после пре-флайта → `docs/BSK-CHEATSHEET.md` §2, ровно один цикл починки.
- Тело ответа не читается из-за лимита перехвата (см. §5) → переключиться на косвенное доказательство, не пытаться «достать токен из браузера».
- Селектор промахнулся 2 раза → перейти на `observe`/`screenshot`, не перебирать классы.

## §3. Пре-флайт (≤ 5 команд, ≤ 1 000 токенов)

```bash
bsk status                     # браузеры, демон, версии
bsk browsers                   # instance id подключённого Chrome
bsk session start --browser <id> --no-focus
bsk tabs list --scope user     # какая вкладка нужна
```

Затем одна вкладка берётся в работу (`bsk_tabs borrow <tabId>`) и больше не переключается. Артефакты создаются **вне репозитория**: `%TEMP%\aicm-artifacts\<тема>\`.

Если задача read-only, `git status --short` в конце должен быть пустым — это часть приёмки.

## §4. Порядок сбора данных (от дешёвого к дорогому)

| Шаг | Инструмент | Когда | Цена |
|---|---|---|---|
| 1 | `bsk_inspect observe` (`maxTokens` 2 000–4 000) | первое знакомство со страницей, поиск ref-ов (`@e61`) | средняя |
| 2 | `bsk_inspect screenshot` | визуальное подтверждение факта (что именно нажали, что появилось) | ~1 картинка |
| 3 | `bsk_inspect html` + **точный** селектор, `maxBytes` ≤ 4096 | нужен фрагмент разметки; **промах = весь документ** | низкая при попадании, ~1 000 токенов при промахе |
| 4 | `debug start` → действие → `debug requests` | перехват сети: сначала только список запросов и метаданные | низкая |
| 5 | `debug export output=<файл>` + shell-анализ | нужны заголовки/тела/тайминги | 0 в контексте |

`bsk_inspect extract` (`extractKind=discover`) на сложных SPA почти бесполезен — находит только `ol`/`ul`.

## §5. Правила работы с перехватом

1. Экспорт перехвата — **всегда** в файл (`debug export output=...`), анализ — `python`/`jq`/`grep`; в контекст — только имена запросов, статусы, размеры и ≤20 строк тела.
2. Тела ответов жёстко ограничены (≈65 536 символов; всё, что больше 262 144 байт, помечается `omitted/body_limit`), `debug replay` невозможен из-за `redacted` заголовка `authorization`. Поэтому «прочитать большое тело» не планируется как шаг — планируется **косвенный вывод** (см. §6).
3. `debug start` привязывается к вкладке: второй запуск без `debugAction: stop` падает с `stop the task's current capture before selecting another tab`.
4. Только одна запись перехвата на задачу; повторный старт — новая запись.

## §6. Как выглядит «решающее измерение»

Плохо: «проверить, откуда берётся текст файла» → 8 гипотез, 3 тупика.

Хорошо: «нажать на чип вложения с включённым перехватом и посмотреть, какой запрос появляется» → один клик даёт `GET files.deepseeksvc.com/api/file?file_id=…&ty=r` с `decoded_bytes=14088` (ровно размер файла) и доказывает, что текст приходит отдельным запросом, а не в `history_messages`.

Правило: если эксперимент не различает две гипотезы — он не нужен.

## §7. Формат выхода

Отчёт ≤ 20 строк, первой строкой — вывод:

```
ВЫВОД: <одно предложение>
1) <ответ на вопрос задачи №1>
2) <ответ на вопрос задачи №2>
3) <решение / вариант правки>
ЦЕНА: <вызовы, артефакты, git status>
```

Артефакты перечисляются путями; в handoff вставляются только выдержки ≤ 20 строк. Код (`core/`, `adapters/`, `tests/`) меняется только если это явно разрешено задачей.

## §8. Готовый блок промпта (вставлять в начало браузерной задачи)

```text
РЕЖИМ: browser-задача (протокол docs/BROWSER-TASK-PROTOCOL.md).
Бюджет: ≤40 инструментальных вызовов, ≤6 на фазу.
Правила:
- тяжёлые ответы (дампы DOM, экспорт перехвата, деревья, бандлы) — в файл вне репозитория, в контекст только выводы и выдержки ≤20 строк;
- сначала observe/screenshot, html — только с точным селектором и maxBytes≤4096;
- один решающий эксперимент вместо проверки всех гипотез;
- известные лимиты и тупики bsk — docs/BSK-CHEATSHEET.md, не переоткрывать;
- git status --short должен остаться пустым (если задача read-only).
Результат: отчёт ≤20 строк по шаблону §7.
```
