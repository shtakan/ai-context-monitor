# SITE-RECIPES — проверенная механика сайтов для браузерных сессий

Назначение: не переоткрывать механику сайта в каждой приёмке. Здесь только
**проверенные** рецепты (дата + чем подтверждено). Если рецепт не сработал —
дописать факт, а не молча обходить.

Правило остановки: механика не ясна после **3** попыток → стоп, запись сюда
(«не проверено»), возврат к задаче.

## AI Studio (`aistudio.google.com`)

Проверено: 2026-11-20, тред `1gHphBl1b-…`, Chrome + bsk 0.3.3.

### Отправка сообщения

- `Enter` — **перенос строки**, не отправка.
- `Ctrl+Enter` — **очищает поле**, не отправляет.
- Отправка — кнопка-иконка справа в композере; стабильного `aria-label` нет.
  Искать в `observe` последнюю кнопку внутри контейнера композера и кликать её;
  после клика проверить, что текст появился в ленте (не остался в поле).

### Новый чат

- Прямой `/prompts/new` редиректит на `/prompt-access-restricted`.
- Рабочий путь: клик по **New chat** в левой навигации (или `+` рядом с chat).
- После создания URL вида `/prompts/<id>`; `convId` = `<id>`.

### Экспорт истории

- Экспорт делает **человек** из попапа расширения («Экспорт JSON»/«Экспорт MD»).
- `chrome-extension://…` и `chrome://extensions` **вне зоны bsk** — не пытаться
  скриптовать; это шаг human-пакета.
- Имя файла: `export-<convId>-<стадия>.json`, складывать в
  `acceptance/BIG-2026-11/2.2/raw/`.

### Файлы/вложения

- Вложение приходит отдельным узлом `[FILE: <имя>]` (иногда с полным текстом
  файла). Роль такого узла в экспорте — известная проблема:
  см. `BUGS.md`, BUG-12 (2026-11-20): после файлового узла роли могут
  смещаться; для приёмки 2.2 это **не** следствие флага `aiCmV2Messages`.

### Полезные проверки в консоли (content-script context)

```js
sessionStorage.getItem('aiCmV2Messages')   // '1' — dual-run включён
window.__aiCmNetMsgs && window.__aiCmNetMsgs.msgs.length
```

`window.__aiCmNetMsgs` живёт в ISOLATED-мире content script: в обычной консоли
страницы его нет; нужен контекст расширения (DevTools → context → AI Context
Monitor) либо лог `[AI CM][v2-messages-json]`.

### bsk 0.5.0: параметры вызовов (проверено 2026-11-20)

- DOM-чтение — `bsk read` / `bsk extract` (без JS); `bsk evaluate` — только для JS
  с возвратом значения.
- `bsk evaluate` требует `--context` и (для строгой политики) `--observation` из
  последнего `bsk cooperate sync`; для меняющейся страницы есть `--unverified`
  или `--expect`.
- Один `evaluate` расходует наблюдение: перед каждым следующим действием — новый
  `bsk cooperate sync` (малый `--max-tokens`, чтобы не тянуть AX-дерево).
- `bsk reload` / `bsk navigate` идут по тому же правилу (`--context` +
  `--observation`).
- Для снятия console без чтения в контекст: `bsk debug start` → `bsk reload` →
  `bsk debug export --json > <файл>`, дальше разбор в shell. Кольцо console
  ограничено 100 записями, лишние считаются в `run.dropped_console` — строки
  `[AI CM]` могут в него не попасть, проверять счётчиком.
- `ms-chat-turn` / `[data-turn-role]` на AI Studio: 45 узлов (вложенные `text-chunk-host`),
  не равно числу сообщений — для сверки ролей не годится без нормализации.

### Роли в экспорте AI Studio (BUG-12)

- `[FILE:]`-узел дублирует ход пользователя: длинный текст с содержимым файла + короткий дубль
  первой строки. Экспортная проекция затем раздаёт роли по чётности индекса
  (`core/content.ts:1065`), и весь хвост инвертируется. Источник (dual-run) при этом корректен.

## Общие правила

- Тяжёлые ответы — в файл; в контекст ≤40 строк.
- Артефакты — с полным путём до начала работы.
- Кириллицу в `evaluate` передавать через `\uXXXX`, иначе CLI ломает кодировку.
- `/tmp` в git-bash ≠ `C:\Temp` для Windows-python; пути объявлять в винном виде.
- Сессия bsk может умереть: `bsk session stop` → новый `start`, вкладку вернуть
  владельцу.
