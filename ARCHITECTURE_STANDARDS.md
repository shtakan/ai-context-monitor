# Стандарты архитектуры и аудита Chrome-расширения

## Архитектурные принципы
- Модульность, разделение ответственности, читаемость.
- Перед изменением кода анализируй текущую архитектуру и предлагай улучшения.
- **Автовыбор варианта (2026-09-07):** при наличии нескольких вариантов решения выбирать самостоятельно вариант, реалистичный и максимально соответствующий мировым стандартам; объявлять выбор одной строкой с обоснованием. Исключение — необратимые действия (удаление данных, публикация, смена мажорной версии): там подтверждение обязательно.

## Соответствие мировым стандартам
- **Manifest V3:** service worker вместо background page, отсутствие remote code.
- **Безопасность:** минимальные разрешения, строгая CSP, отсутствие inline-скриптов, корректная обработка данных.
- **Производительность:** асинхронные операции, эффективное использование chrome.storage, предотвращение утечек памяти.
- **Обработка ошибок:** все асинхронные вызовы в try/catch, понятные сообщения.
- **Локализация:** при необходимости i18n.
- **Chrome Web Store:** отсутствие запрещённого контента, корректные метаданные.

## Действия при получении логов/скриншотов
- Не только интерпретируй ошибку, но и выявляй потенциальные архитектурные проблемы, предлагай превентивные меры.

## Полный аудит
- После значительных изменений или по запросу пользователя проводи полный аудит: отчёт с оценкой качества, рисками, рекомендациями.

## Дополнение v1.14.0 (2026-08-31): стандарт полноты истории Gemini

1. Разделять источники: passive (хвостовой снимок), pag (тихая пагинация по серверным курсорам), vf5 (виртуальный F5), tape (локальный кэш). Merge строго по id; same-conv-union для пересечений; disjoint-reset только при смене convId.
2. Оракул полноты нециркулярен: совпадение хешей — только предварительный гейт. Источники complete: probe-terminal (контрольный запрос с широким курсором: 0 новых старших id и нет курсора), no-older-history (первый снимок без курсора продолжения), loader-stable-stop (loader done reason=top И base >= floor). Гейты: loader-max-not-top, below-floor.
3. Двухуровневая загрузка без race condition: тихая пагинация — основная; fallback-real-scroll (скрытый скролл скроллера) — страховка; арбитраж одним автоматом состояний и латчами. Overlay на body вместо скрытия контейнеров чата (виртуализация сервиса не ломается).
4. High-water-mark (tape): пол не опускается ниже сохранённого; после F5 tape-restore action=used, бейдж сразу на полу.
5. Автоэкспорт — фича Gemini: порог (1–100) ИЛИ base-complete, латч «один раз на чат», [LOW CONFIDENCE]_ только при baseComplete=0; deferred-timeout 60s; re-check на переходе baseComplete 0→1.
6. Жизненный цикл MV3: visibilitychange/pagehide — снятие overlay; conv-switch — сброс состояний; Service Worker может выгружаться — состояние восстанавливается из tape.

### Консервативный дефолт оракула полноты (H9, 2026-09-04)
7. full-confidence complete объявляется ТОЛЬКО из серверно-авторитетных точек (probe-terminal, no-older-history, чистое исчерпание курсора пагинации без обрыва) либо из памятно-подтверждённых (floor-confirmed; loader-stable-stop — при floor>0 И реальном росте скроллера). Слабые точки — DOM-top при floor=0 (вакуум памятных гейтов) и сравнение собственных хешей (циркулярный scroll-top-proof) — high-confidence complete НЕ объявляют; их закрывают гейты untrustedTopVerdict / lastPagStepBroken (ложный doneReason='top' → collapse; оборванный финальный шаг пагинации → подавление scroll-top-proof, уход в probe).
8. Авторитетный оракул не отключается одним битым ответом: хранить last-good wide-cursor / probe-метаданные (серверный firstHash и курсор последней «живой» страницы); обрыв финального шага пагинации не должен лишать probe терминального подтверждения (H9b-кандидат).

## Мировая изоляция — эталон
- MAIN-перехватчики НЕ используют chrome.* API — только DOM-наблюдение.
- Каналы MAIN↔ISOLATED: исключительно CustomEvent / postMessage.
- Аудит (срез 2) подтвердил 0 нарушений. Сохранять как инвариант при добавлении новых перехватчиков.

## Стандарт тестирования полноты истории (2026-09-06)

**Принцип:** полнота истории доказывается **только сравнением экспортного файла с реальным содержимым чата**, а не логами.

**Алгоритм верификации (обязателен для всех тестов полноты):**
1. Экспорт: вызвать автоэкспорт или ручной экспорт (кнопка «Сохранить .txt»)
2. Скролл вверх: программно прокрутить чат до верха (scrollTop=0) и дождаться стабилизации scrollHeight
3. Чтение краёв чата:
   - Первые 3 сообщения из DOM (голова истории)
   - Последние 3 сообщения из DOM (хвост истории)
4. Сравнение с экспортом:
   - Экспортный файл должен содержать **все** сообщения из DOM
   - Первые 3 сообщения экспорта должны совпадать с первыми 3 из DOM (порядок и текст)
   - Последние 3 сообщения экспорта должны совпадать с последними 3 из DOM (порядок и текст)
5. Критерий полноты: `exportedMsgs.length === domMsgs.length` И все сообщения из DOM присутствуют в экспорте

**Почему это сильнее логов:**
- Логи могут лгать (баг A5: циркулярный scroll-top-proof)
- Логи не видят контент (только счётчики и хеши)
- Экспорт + скролл видят **реальный контент** в глазах пользователя

**Применение:** все тесты полноты (gemini-floor-confirmed, gemini-tape-protect, gemini-untrusted-top, gemini-collapse-guard и т.д.) должны включать этот алгоритм верификации.

## Политика приватности фикстур (2026-09-09)

**Принцип:** в репозитории — только синтетические или анонимизированные фикстуры.
- В git допускаются: синтетические фикстуры, собранные в репо (например `gemini-head-sample.min.txt`), и анонимизированные дампы без персональных данных.
- Вне git остаются: живые экспорты чатов (личные образцы вида `chatgpt-conversation-sample.json`, `gemini-head-sample.txt`, `google-folwr-*.txt`), скриншоты с перепиской (`docs/screenshots/*.png`) и персональные дампы (`docs/order-bug/*.txt`, `tests/fixtures/perplexity-thread-rest.json`).
- Тесты, зависящие от живых фикстур, обязаны быть skip-if-absent (`fs.existsSync` → `describe.skip`/`it.skip` + `console.info` «фикстура отсутствует — пропуск»), чтобы CI оставался зелёным без приватных данных. Прецедент — 8c36ee1 (ChatGPT), расширен на все сервисы (Gemini, Perplexity, H26).
- Тесты на синтетических фикстурах (включая `*.min.txt`) гейту не подлежат — они обязаны работать всегда.

## Осознанные трейд-оффы
- (а) session-латчи O3 в storage.session (TRUSTED_AND_UNTRUSTED_CONTEXTS) доступны content-скриптам всех сайтов — принято осознанно ради кросс-табового already-fired автоэкспорта.
- (б) BYOK-ключ Gemini хранится в chrome.storage.local в открытом виде — стандартная практика BYOK-расширений, риск задокументирован. Честная альтернатива (прокси без хранения ключа) отклонена как невостребованная.

## Оси порогов — разные сущности (не унифицировать)
- widget zoneColor 50/80 — UX-заливка виджета.
- proactive [70,85,95] — уведомления/бейдж, настраиваемы в options, S2.
- автоэкспорт pct 1–100 — глобальный + per-site, S2.
- safePct — per-site авто-порог виджета.
- Унификация НЕ требуется — оси решают разные задачи.

## Политика версия-маркеров
- Комментарии vNN/O*/H* не чистятся ретроспективно.
- При касании функции маркеры мигрируют в RELEASE_CHECKLIST/CHANGELOG; имена переменных-артефактов (eO3D14 и т.п.) очищаются при следующем касании.
